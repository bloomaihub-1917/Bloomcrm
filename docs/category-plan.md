## 없는 것·어긋난 것

1. **시공사**: 참가 유형으로 32줄 저장됐는데 `part_types`에 없다 → 색·필터에서 빠진다(RP에는 있음).
   이 사람들 15명은 `cat`도 빈칸.
2. **Seller**: 카테고리에 대문자 `Seller` 10명. 코드의 `CAT_KEYS`·`CL`에는 없다(DB 목록에만 있음). 셀러는 행사 참가 유형(`셀러`)과 겹친다.
3. **Student·organizer**: 목록에만 있고 쓰는 사람 0명. 반대로 `bd` 102명은 참여 기록이 하나도 없다 — 행사 역할이 아니라 «영업 대상» 표시로 쓰이고 있다.
4. **카테고리 ↔ 참가 유형 이중 관리**: VIP로 참여한 9명이 `cat=speaker`. 연사·전시·셀러가 사람에도, 행사 참여에도 따로 적힌다.
5. **분야**: 화면의 «분야(큰 갈래)»는 `sectors.domain` 4개인데, 연락처 상세의 «분야»는 `contacts.beat`(섹터 이름 복사본)를 보여 준다. 같은 이름이 다른 것을 가리킨다.
6. **섹터에 위아래가 없다**: `parent` 칸이 있지만 57개 모두 비어 있다. «건축 업종 미정»·«이벤트·MICE 업종 미정»·«바이오·임상 업종 미정»처럼 «미정»이 섹터 하나로 들어가 있다.
   «공공기관»(common)과 «공공기관·협회»(건축), «대학교»와 «대학·연구소»와 «학계·연구»처럼 domain마다 비슷한 것이 따로 있다.
7. **orgs.sectors 구분자**: 섹터 이름 안에 `,` `/`가 있어(«판촉(기념품,굿즈)», «LED/LCD 디스플레이») 여러 섹터를 이어 붙인 값을 나눌 때 깨질 수 있다 — 저장 구분자 확인 필요.
8. 연락처 18명은 소속이 적혀 있는데 `org_id`(기업DB) 연결이 없다. 기업 59곳은 섹터가 비어 있다.

## 정리 방향 (제안)

**사람에 붙는 것과 행사마다 달라지는 것을 나눈다.**

- **행사 참가 유형**(`participations.role`) 하나가 «이 행사에서 무엇이었나»의 정본.
  연사·VIP·전시참가기업·셀러·바이어·시공사·스폰서·참가자. 목록은 `part_types` 한 곳.
- **사람 카테고리**(`contacts.cat`)는 없애거나 «관계» 하나로 줄인다 — 행사 참여에서 계산해 보여 주고(가장 최근 역할),
  참여가 없는 사람만 손으로 정한다(잠재 고객·BD 대상 등). Master DB 위 칩도 참가 유형으로 거른다.
- **기업 분류는 기업에만**: 분야(domain) → 섹터(sectors) 2단. 사람 화면에서는 «소속 기업의 섹터»로 읽기만 한다.
  `contacts.beat`는 기업 섹터로 옮긴 뒤 더 이상 쓰지 않는다.

## 순서

1. **바로 고칠 것(작음)** — ~~시공사를 `part_types`에 추가~~ → 시공사는 참가 유형이 아니다(기업 종류 «벤더시공사», 이벤트코리아에선 셀러로 참여). BIO-002 시공사 32줄은 백업 후 뺐다(11-05), `Seller`→셀러 정리, 빈칸 cat 20명 채우기, 안 쓰는 Student·organizer 숨김(active=no).
2. **분야 이름 통일** — 화면의 «분야»는 domain만 뜻하게. 연락처 상세의 beat 표시를 «소속 기업 섹터»로 바꾼다.
3. **섹터 표 정리** — domain별 중복(공공기관/대학) 합치기, «업종 미정»은 섹터가 아니라 빈칸으로. 이름에서 `,` `/` 빼거나 구분자 바꾸기. 바꾸기 전에 `orgs.sectors`·`contacts.beat`·`crm_targets.sector`를 함께 옮기는 스크립트(시험 실행 → `--apply`).
4. **beat → 기업 섹터 옮기기** — 사람 beat와 소속 기업 섹터가 다를 때 목록으로 뽑아 확인 후 옮김. 기업 연결 없는 18명 먼저 연결.
5. **사람 카테고리 줄이기** — cat 대신 참가 유형에서 계산. Master DB 칩·보기 줄·연락처 추가 창을 같은 목록으로. bd는 «영업 대상» 표시로 따로.

1번은 데이터만 조금 바꾸면 되고, 3~5번은 화면과 저장이 같이 바뀌어 새 브랜치에서 한다.

## 맨 위 축 — DB 갈래 (2026-11-05 사용자와 정함)

연락처마다 `contacts.origin`에 «처음 들어온 길»을 둔다. 이후 이력은 행사 참여 기록이 보여 준다.

| 값 | 뜻 | 처음 채운 수 |
|---|---|---|
| `ours` | 우리가 수주한 행사를 진행하며 수집 (연사·전시 담당자·GPBFair 셀러·AIASK 연사) | 294 |
| `other` | 타 행사의 참가자 데이터 (타 행사 독립부스 시공사 명단, 플랫폼 데이터) | 51 |
| `sales` | 우리 행사로 끌어오려고 모은 DB (셀러·바이어 명단, 2026 KIC 독립부스 시공사, 09-16 건축 명단, EVK·홍보메일) | 661 |

- 수주 행사라도 «그쪽이 가진 데이터로 참가 독려»한 명단은 `sales`다(09-16 건축 96명, KIC 독립부스 시공사).
- 채우기 규칙: `backend-node/db/oneoff/fill-contact-origin.js`. 새 연락처를 넣는 화면·업로드는 아직 이 칸을 채우지 않는다 → 다음 단계에서 추가 창·업로드에 «DB 갈래» 고르기를 넣고 Master DB 맨 위 거르기로 쓴다.
- 한 사람이 한 행사에서 참가 유형 여럿을 가질 수 있다 — 주최측이 전시로도 참여(전서빈, 2025·2026 KIC 주최사+전시참가기업). 사람 카테고리 하나로는 담을 수 없으니 5단계에서 참여 기록으로 계산한다.

**MICE 섹터는 2단(`sectors.parent`)으로** — 지금 21개가 모두 최상위.

| 위(큰 갈래) | 아래(섹터) |
|---|---|
| 시공·설치 | 부스/무대/구조물 (구조물·부스·무대만) |
| 전기·설비 | 전기 · 급배수·압축공기 · 가스설비 · 방염 (뒤 셋은 11-09 섹터로 만듦, `db/seeds/seed-facility-sectors.js`) |
| 제작·렌탈 | 판촉(기념품,굿즈) · 인쇄/출력 · 행사가구/텐트/렌탈 |
| 연출·기술 | 영상 · LED/LCD 디스플레이 · 음향 · 조명 · 이벤트(특효)장치/장비 · IT솔루션 |
| 운영·서비스 | 대행사 · 엔터에이전시(MC/공연) · 통역 · 케이터링 · 교통 · 프리랜서 |
| 장소 | 베뉴 |
| 기타 | 이벤트·MICE 기타 |

- «이벤트·MICE 업종 미정»은 섹터가 아니라 빈칸으로(36곳은 시공사라 «부스/무대/구조물»).
- «이벤트 부스»는 프로그램·체험·포토 업체라 이름을 «이벤트 프로그램/체험»으로 바꿔 «부스/무대/구조물»(물리적 시공)과 구분.
- «기타» 20곳은 제품 정보로 전기·인쇄/출력·판촉으로 옮기고 나머지만 남김.

- 시공과 렌탈의 구분(사용자 지적 11-09): **새로 짜서 세우면 «시공·설치»(부스/무대/구조물만 — 전기는 «전기·설비» 갈래), 있는 물품을 빌려주면 «제작·렌탈»(행사가구/텐트/렌탈)**. 한 업체가 둘 다 하면 주된 매출 쪽 하나를 고르고 나머지는 메모에 적는다. 렌탈 부스(렌탈·부스·백월)를 파는 곳은 «부스/무대/구조물»에 이미 일부 있어 건별로 확인한다.
- 한 업체가 두 섹터를 하면 `orgs.sectors`에 `|`로 둘 다 적고 **첫 번째가 주력**(예: 테이너·포터블엑스 = `부스/무대/구조물|행사가구/텐트/렌탈`, 주문 제작이 주). 섹터로 거를 땐 둘 다 걸리고, 큰 갈래·대표 표시는 첫 번째 기준.

### «대행사» = 우리와 같은 기획·운영대행사(경쟁사) — 11-09 사용자 정함
- 별도 기업 종류(`경쟁사`)는 만들지 않고 섹터 **대행사**를 그대로 쓴다. 제일기획·인터컴·오프너디오씨·메쎄이상 같은 곳이 들어온다(DB에는 아직 없음).
- 대행사의 **유형은 태그**로 적는다 — 종합광고·브랜드 / PCO·컨벤션 / 전시 주최·기획 / 이벤트·프로모션. 기업에는 태그 칸이 없어(연락처 `tags`만 있음) 쉼표 태그를 이미 쓰는 **`orgs.products`에 적기로 정했다**(11-09). `products`의 뜻: 일반 기업은 «취급 품목», **MICE 업계 기업은 «주로 하는 유형»**. 태그 칸을 새로 만드는 안은 쓰지 않는다.
- 지금 «대행사» 섹터 46곳 중 약 10곳은 «MICE» 태그만 붙은 공급업체(조명·특효·렌탈·IT·마케팅·시공)로 보여 건별 확인 후 섹터를 바로잡는다.

### 기업DB는 종류가 아니라 분야·섹터가 중심 — 11-09 사용자 정함
- 기업DB 위쪽 탭을 **분야**(이벤트·MICE / 바이오·임상 / 건축 / 공통 / 분야 미분류)로 바꿨다. 종류(전시참가기업·잠재고객사·벤더시공사)는 거르기 줄의 작은 선택 «종류 전체»로 내렸다.
- 기업 목록 정렬에 «섹터 순»(큰 갈래 순서, 기업은 첫 섹터가 주력)을 넣고, 섹터 칩도 같은 순서로 줄 세운다.
- 벤더시공사를 «등록 시공업체»로만 줄이는 재분류(124곳 강등)는 하지 않기로 했다 — 종류가 중요하지 않으므로. 등록 전시장은 기업 메모 «코엑스·킨텍스 등록업체(2026) — 분류»로 남긴다.
