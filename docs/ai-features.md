# AI(Claude API) 기능 정리와 디벨롭 방향

작성 2026-10-29 · 기준 코드 `backend-node/routes/ai.js`

## 1. 구조 한눈에

```
화면(js/modules/*) ──aiXxx()──▶ js/api.js aiApi() ──▶ /api/ai/* (requireAuth)
                                                     └▶ backend-node/routes/ai.js ──▶ Claude API
```

- 모델: `claude-sonnet-5-5` 하나 (`MODEL` 상수), `server-side-fallback` 베타로 과부하 시 대체 모델 사용
- 모든 답은 **JSON 스키마 고정 출력**(`output_config.format: json_schema`) → 서버가 한 번 더 걸러 화면에 넘긴다
  (없는 칸·없는 단계 key·없는 탭은 버리거나 `none`으로 바꿈)
- `ANTHROPIC_API_KEY`가 없으면 `/status`가 `enabled:false` → 화면은 AI 없이 기존 규칙으로 동작
- 테스트 모드(서버 없음)에서는 쓸 수 없음 (`aiApi`가 `offline` 반환)
- Vercel 함수 60초 제한 때문에 `timeout: 55000, maxRetries: 0`
- **설정 › ✨ AI 설정**(`js/modules/ai-settings.js`, `GET/PUT /api/ai/config`): 기능마다 켜기/끄기·모델(Sonnet/Haiku/Opus)·생각 깊이, 한 달 호출 한도, 이번 달 사용량. 저장은 `settings` key=`ai_config`, 사용량은 `ai_usage` 테이블(기능·모델·토큰만, 내용은 안 남김). 모든 라우트는 `askJson()` 하나로 호출
- **개인정보 원칙**(2026-10-08): 이름·메일 주소·메일 본문은 보내지 않는다.
  예외는 업체 소개서 PDF(2026-10-26, 공개 홍보물)

## 2. 현재 AI 기능 10곳

### 공통 설계 패턴 (잘 되어 있는 점)
- **AI는 계획만, 실행은 화면**: 검색(4·5)은 조건표만 받고 실제 거르기는 로컬 데이터로 → 개인정보가 나가지 않고 결과도 검증 가능
- **AI 답 → 실제 단추**: 상담(7·8)의 할 일이 바로 기능으로 이어짐. 없는 key는 서버에서 `none`으로
- **사람이 최종 결정**: 회사 합치기·국가/업종·메일은 모두 사람이 확인 후 저장/발송
- **변수 틀**: 메일 초안은 이름 대신 변수로 받아 화면이 채움 → 양식 보관함에 저장하면 다음엔 AI 없이 재사용

## 3. 현재 가능한 범위 — 지금 구조 그대로 바로 할 수 있는 개선

### 3-1. 코드 정리·비용
- **공통 호출 함수로 묶기**: 10개 라우트가 `messages.create` + 오류 처리 15줄을 복붙 중 → `askJson({ prompt|content, schema, effort, maxTokens })` 하나로. 모델·타임아웃 변경이 한 곳에서 끝남
- **작업별 모델 나누기**: 열 맞추기·검색 조건표·국가/업종처럼 단순 분류는 Haiku로, 상담·메일 초안은 Sonnet 유지 → 비용·속도 개선
- **프롬프트 캐싱**: `SPEAKER_CRM_GUIDE`, `EXH_CRM_GUIDE`, 회사 목록(최대 3000개, `/company-pairs`)처럼 매번 같은 앞부분에 `cache_control` → 반복 호출 비용 절감
- **사용량 기록**: 응답의 `usage`(입력/출력 토큰)를 `activity_log` 또는 별도 테이블에 기능별로 남겨 월 비용 파악

### 3-2. 기존 기능 확장
- **회사 쌍 찾기 큰 목록 대응**: 기업이 많으면 55초 안에 못 끝남 → 초성/알파벳 묶음으로 나눠 여러 번 호출 후 합치기
- **질문으로 찾기 기록**: 자주 쓰는 질문 + 해석된 조건표를 «저장된 검색»으로 남기기 (다시 부를 때 AI 호출 없음)
- **메일 초안 → 리마인더 문구**: «요청 N일째» 리마인더(마감 대신 리마인더 원칙)에 맞춘 독촉 초안 프리셋
- **상담에 «되돌리기/편집» 이외 단추 추가**: 예) 참가사 상담에서 «인보이스 재발행» 같은 정산 동작을 바로 여는 action
- **소개서 요약을 다른 문서로**: 견적서 비교(여러 업체 PDF → 단가표) — 같은 PDF 예외 범위 안에서 가능
- **연사 약력 정리**: 연사가 직접 보낸 공개 약력/CV(발표용 공개 자료)를 프로그램북 길이(국/영 N자)로 줄이기 — 단, 개인정보 원칙상 사용자 결정 필요

### 3-3. 안정성
- 스키마 출력이라 파싱 실패는 드물지만 `JSON.parse` 실패 시 전용 메시지
- AI 꺼짐/실패 시 화면 안내 문구 통일, «AI 없이 계속» 경로 점검

## 4. 추후 디벨롭 범위 — 구조 변경이나 정책 결정이 필요한 것

### 4-1. 받은 메일 다루기 (개인정보 원칙 재검토 필요)
지금은 메일 본문을 안 보내므로 아래는 **로컬 마스킹 후 보내기** 또는 **원칙 변경** 결정이 먼저.
- 받은 메일 분류: 회신 종류(참석 확정/거절/자료 첨부/문의) 자동 태그 → 연락 단계 자동 진행 제안
- 첨부 자동 인식: «발표자료 받음», «사진 받음»을 감지해 자료 칸 체크 제안
- 회신 초안을 받은 메일 내용에 맞춰 쓰기

### 4-2. 에이전트형 기능 (tool use)
- 지금은 «조건표 1회 → 화면이 실행». 다음 단계는 Claude가 CRM 함수(검색, 단계 조회, 초안 생성)를 **도구로 호출**하며 여러 단계를 스스로 진행
  - 예) «KIC 2026 연사 중 발표자료 안 낸 사람에게 독촉 초안 만들어줘» → 검색 → 단계 확인 → 일괄 초안까지
- 실행(발송·저장)은 반드시 사람 확인 단계를 남긴다

### 4-3. 대량·백그라운드 작업
- **Message Batches API**: 기업 수천 곳 국가/업종 채우기, 전체 회사 중복 검사처럼 급하지 않은 일을 밤에 일괄 처리(비용 50%↓, 60초 제한 회피)
- cron(`/api/cron`)에 붙여 주기적 데이터 정리 리포트

### 4-4. 외부 정보 결합
- **웹 검색 도구**로 기업 정보 보강: 공식 홈페이지·본사 국가·업종을 출처와 함께 제안 (`/org-enrich` 확장)
- 연사 공개 프로필(소속 기관 페이지) 확인 — 개인정보 정책 결정 후

### 4-5. 행사 단위 인사이트
- 행사 종료 후 리포트: 참가사·연사 진행 통계(이미 있는 숫자)를 넣어 운영 회고 문장 생성 — 숫자만 보내므로 원칙과 충돌 없음
- 다음 행사 섭외 후보 추천: 과거 참가 이력 패턴 → 재참가 가능성 높은 기업 목록 (계산은 로컬, 설명만 AI)

### 4-6. 운영
- 기능별 AI 사용 on/off·월 한도를 행사 설정/관리자 설정에서 조정
- 프롬프트를 코드 밖(설정 테이블)으로 빼서 문구 조정 시 배포 없이 수정

## 5. 우선순위 제안

| 순서 | 항목 | 이유 |
|---|---|---|
| 1 | 공통 호출 함수 + 사용량 기록 | 이후 모든 작업의 기반, 비용 가시화 |
| 2 | 작업별 모델 분리 + 프롬프트 캐싱 | 바로 비용·속도 이득 |
| 3 | 회사 쌍 찾기 분할 호출 / Batches | 기업DB가 커질수록 지금 실패함 |
| 4 | 리마인더 초안·저장된 검색 | 현업 체감 큰 작은 기능 |
| 5 | 받은 메일 분류 | 효과 가장 크지만 개인정보 정책 결정 먼저 |
| 6 | tool use 에이전트 | 위 기반이 갖춰진 뒤 |
