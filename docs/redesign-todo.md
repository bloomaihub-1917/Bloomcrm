# 전체 수정 때 반영할 것

디자인·구조를 한꺼번에 다시 잡을 때 같이 고칠 목록. 하나씩 고치지 않고 모아 둔다.

## 연락처 분류 (2026-11-04 메모)

- **카테고리가 너무 복잡하다.** 연락처 추가 창의 «카테고리»(일반참가자·연사·VIP·전시 기업 …),
  Master DB 위쪽 칩(전체·연사·VIP·일반참가자·전시 기업), 보기 줄(연사·스폰서·투자자·바이어),
  행사 참여의 «참가 유형»(PART_TYPES)이 서로 겹친다. 사람에 붙는 값과 행사마다 달라지는 값(참가 유형)을
  나눠 한 갈래로 줄인다.
- **분야와 섹터를 구분되게.** 둘 다 기업 분류(분야 = 큰 갈래, 섹터 = 분야 안 세부)인데
  사람 칸과 섞여 보여 헷갈린다. 지금은 연락처 추가 창에서 «소속 기업 분류» 상자로 묶어만 두었다.
  전체 수정 때 이름·위치(사람 정보 vs 기업 정보)를 함께 정리한다.
