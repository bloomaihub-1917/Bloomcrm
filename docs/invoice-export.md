# 인보이스 양식 내보내기

전시 → 참가기업 드로어 → **정산** 탭 → 인보이스 줄의 `양식 내려받기` 버튼.
그 기업의 금액 항목을 쓰던 인보이스 양식(국문·영문 두 시트)에 채워 엑셀로 받는다.

## 왜 만드나

정산 탭에서 인보이스를 한 줄 만들면 금액·발송일·입금 기한은 CRM에 남는다.
그런데 기업에 실제로 보내는 것은 양식에 맞춰 찍은 엑셀 한 장이고, 그 한 장은
사람이 만들었다 — 양식을 복사해 열고, 상호·부스번호·인보이스 번호를 적고,
품목을 한 줄씩 옮겨 적고, 단가를 다시 두드렸다. 59개사면 59번이다.

옮겨 적는 동안 숫자는 갈라진다. CRM에서 항목 하나를 고쳐도 이미 만든 엑셀은
따라오지 않고, 어느 쪽이 맞는지는 두 개를 나란히 놓고 대조해야만 알 수 있다.

## 양식 파일은 저장소에 없다

양식에는 **직인 이미지와 계좌번호**가 박혀 있고 이 저장소는 공개다. 그래서
다른 실데이터와 같이 `Data/` 아래에 두고(`Data/`는 `.gitignore`에 있다) 실행할
때 읽어 온다.

    Data/인보이스_양식.xlsx

그 자리에 없으면 파일 고르기 창이 뜬다. 한 번 고르면 그 세션 동안 다시 쓴다.

### 양식을 다시 만들어야 할 때

받은 양식(`2026 KIC Exhibition 인보이스(템플릿)_양식.xlsx`)을 그대로 쓰지 않고
두 가지를 손봐서 넣는다. 두 단계 모두 스크립트로 남겨 두었다.

```bash
python scripts/prep-invoice-logo.py "<받은 양식>.xlsx" /tmp/step1.xlsx
node scripts/build-invoice-template.js /tmp/step1.xlsx "Data/인보이스_양식.xlsx"
```

1. **로고 자르기** (`prep-invoice-logo.py`) — 받은 양식은 머리 로고의 흰 여백을
   엑셀 자르기(`srcRect`)로 감춰 두었다. 실행 시점에 쓰는 ExcelJS는 파일을 다시
   쓸 때 이 자르기를 버려서, 그대로 두면 로고가 여백째로 늘어나 찌그러진 채
   인보이스가 나간다. 이미지를 미리 잘라 넣고 `srcRect`를 지운다.

2. **항목 칸 24줄로 늘리기** (`build-invoice-template.js`) — 받은 양식은 국문
   9줄 · 영문 11줄이다. 항목이 많은 기업은 여기에 안 들어간다. 줄 수를 미리
   늘려 두고 실행 시점에는 남는 줄을 **숨기기만** 한다.

   왜 실행 시점에 행을 넣거나 빼지 않나 — ExcelJS의 행 삭제(`spliceRows`)는
   병합·그림·수식을 따라 옮기지 못한다. TOTAL·계좌 안내·직인이 통째로 어긋나고
   병합이 겹쳐 엑셀이 파일을 고장 난 것으로 본다(실제로 그렇게 나왔다). 행을
   늘리는 `duplicateRow`는 되지만 늘린 뒤의 좌표와 메모리 안의 좌표가 갈려서
   병합을 다시 그리는 일이 위태롭다. 그래서 그 위험한 일은 스크립트에서 한 번만
   하고 결과를 눈으로 확인한다.

   24줄로 모자라면 스크립트의 `ROWS`와 `exh-invoice.js`의 `LAST_ROW`를 같이
   고쳐 다시 돌린다.

이 스크립트에는 `exceljs`가 필요하다(`npm i exceljs`, 앱은 CDN에서 받아 쓴다).

## 무엇이 들어가나

| 양식 칸 | 값 |
|---|---|
| No. (C3) | `EX-{부스번호}-{발행 순번}` — 쓰던 규칙 그대로 |
| 발행일 (C4) | 인보이스의 발송일. 비어 있으면 오늘 |
| 수신인 (C5) | 국문 시트는 국문 상호, 영문 시트는 영문 상호 |
| Booth No. (L3) | `exhibitors.booth_no` 그대로 |
| 구분 (B) | 항목 분류 — 부스 타입 / 비품 임대 / 사인물 프린팅 / 기타 |
| 상세 (C:E) | 국문은 CRM의 품목명 그대로, 영문은 카탈로그 영문명(`{코드} {name_en}`) |
| 수량·단가 (F·H) | 금액 항목의 수량·단가 |
| 금액 (J:K) | `=단가×수량` |
| TOTAL (J) | `=SUM(...)` |
| 납입일자 안내 (L) | `납입기한: ...` / `Due Date: ...` — 인보이스의 입금 예정일 |

인보이스 번호의 순번은 그 기업의 **몇 번째 인보이스인가**다. 금액을 고쳐 다시
발행하면 옛 건을 무효로 두고 새 줄을 만드는데, 그 새 줄이 `-02`, `-03`이 된다.

## 금액은 어디서 오나

**인보이스 줄에 적은 금액이 아니라 금액 항목 합계**가 들어간다. 인보이스 줄의
금액은 CRM 안의 청구액이고, 기업에 보내는 문서에는 무엇을 얼마어치 받는지가
줄 단위로 적혀야 한다. 두 값이 다르면 내보낸 뒤에 알린다 — 대개 항목을 고치고
인보이스 줄의 금액을 안 고쳤다는 뜻이다.

- **청구 제외**(추가 배지처럼 우리가 청구하지 않는 항목)와 **취소**된 줄은 빠진다.
- **금액 칸은 수식으로 둔다.** 값으로 박아 넣으면 받은 사람이 수량 한 칸을
  고쳤을 때 합계가 따라오지 않는다.
- 다만 CRM의 금액이 수량×단가와 맞지 않는 줄(금액만 적어 둔 항목 등)은 **금액을
  그대로 적는다.** 단가를 금액÷수량으로 꾸며 넣으면 나누어떨어지지 않는 줄에서
  합계가 청구액과 어긋난다 — 없는 단가를 만들어 넣지 않는다.

## 통화 — 한 장에 한 통화만

한 기업 안에서 부스는 달러, 비품은 원화로 갈리는 일이 실제로 있다. 인보이스
한 장에 두 통화를 담을 수는 없으므로 **그 인보이스의 통화와 같은 항목만** 싣고,
빠진 항목이 있으면 몇 건인지 알린다. 나머지는 통화를 바꿔 인보이스를 한 장 더
만들어 내보낸다 — 지금도 원화·달러를 따로 발행해 왔다.

통화 기호(`₩` / `$`)와 금액 표시형식은 코드에 적지 않고 **양식의 시트에서 읽어
온다.** 국문 시트에 원화 쪽, 영문 시트에 달러 쪽이 이미 들어 있어서, 코드에
다시 적으면 두 곳이 갈린다.

## 내보낸 뒤에 알리는 것

파일은 나가지만 보내기 전에 눈으로 봐야 하는 값들이다.

- 항목이 24건을 넘어 뒤가 빠졌을 때
- 그 인보이스의 통화가 아닌 항목이 빠졌을 때
- 인보이스 줄에 적은 금액과 항목 합계가 다를 때

## 파일 이름

    {행사} Exhibition Invoice_{영문 상호}_{인보이스 번호}.xlsx
