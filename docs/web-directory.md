# 웹디렉토리 — 프로그램북 게재 정보의 공개 화면

프로그램북(도록)에 실은 참가기업 정보를 그대로 웹에서 보여준다. 인쇄물에는 이
주소(또는 QR)만 싣고, 관람객은 현장에서 폰으로 열어 기업을 찾는다.

인쇄물과 다른 점은 두 가지다. 지면 제약이 없어 회사소개를 자르지 않고, 인쇄
이후에 바뀐 내용(오탈자·연락처·부스 이동)을 고칠 수 있다 — CRM 전시 탭에서
고치면 최대 5분 뒤 반영된다(캐시).

## 주소

```
GET /d/<행사슬러그>        기업 목록 (HTML 한 페이지)
GET /d/<행사슬러그>.json   같은 내용의 JSON
```

행사 슬러그는 따로 저장하지 않는다. `events.id`와 `events.short`를 소문자로
누르고 공백을 `-`로 바꿔 견주므로, `2026 KIC`는 `/d/2026-kic`으로 열린다.
행사를 새로 만들면 주소가 저절로 생긴다.

예: `https://<백엔드>.vercel.app/d/2026-kic`

짧은 주소가 필요하면 도메인 쪽에서 리다이렉트를 걸어 쓴다(코드는 안 건드린다).

## 무엇이 공개되는가

`exhibitors`에서 아래 칸만 내보낸다.

| 화면 | 컬럼 |
| --- | --- |
| 순번 | `book_order` |
| 기업명 | `company_name` |
| 부스 | `booth_no` |
| 회사소개 | `book_intro` |
| 주소 | `book_address` |
| 연락처 | `book_phone` |
| 웹사이트 | `book_website` |
| 스폰서 등급 | `grade` (DIA/GOLD/SILVER/BRONZE만) |

내보낼 칸을 `routes/public.js`에서 하나씩 적어 고른다. `SELECT *`로 넘기면
나중에 컬럼이 늘어날 때 입금·세금계산서·담당자 연락처가 조용히 함께 나간다.

`status = '취소'`인 기업과 이름이 빈 행은 뺀다. `book_*`이 아직 안 채워진
기업은 이름과 부스번호만 나온다 — 자료를 못 받은 것도 사실이므로, 빈 자리를
숨기지 않고 그대로 둔다.

정렬은 `book_order`를 숫자로 읽어 세운다(글자 칸이라 그대로 두면 10이 9보다
앞에 온다). 번호가 없는 기업은 뒤로 보내 이름순으로 놓는다.

## 스폰서

`grade`가 DIA·GOLD·SILVER·BRONZE인 기업은 스폰서로 보고 **스폰서** 구역에
따로 묶어, 등급 배지와 등급색 띠를 달고 기업명을 키운다. 인쇄물에서 앞장에
크게 실리는 자리를 웹에서도 같게 만드는 것이다.

지금은 순번 1~9가 정확히 그 네 등급이지만 **번호로 가르지 않는다**. 도록
번호는 지면 사정으로 바뀌는 값이고(서울대·분당서울대를 44/45로 나눈 것처럼),
스폰서 여부를 말해 주는 건 등급이다. 등급만 바꿔 주면 화면이 따라온다.

`Exhibitor`는 등급이 아니라 "스폰서가 아니다"는 표시라 배지를 달지 않고,
JSON에서도 `sponsor: ""`로 비운다 — 그대로 흘리면 읽는 쪽이 등급으로 읽는다.

구역 안 순서는 도록 순번 그대로다. 스폰서가 이미 앞번호를 받았고, 인쇄물과
웹의 순서가 어긋나면 번호로 찾는 사람이 헤맨다. 검색으로 한 구역이 다 걸러지면
그 구역 제목도 함께 숨는다.

## 만들어 둔 방식

- 인증이 없다. QR을 찍은 사람이 곧 관람객이다. 대신 `/api`와 별도로 분당 300회
  요청 제한을 걸었다.
- HTML을 서버가 다 만들어 내려준다. 행사장 네트워크가 느려도 글이 먼저 보여야
  하고, 검색은 목록이 이미 손에 있으니 브라우저에서 거르기만 한다.
- `Cache-Control: public, max-age=300` — 관람객 수백 명이 같은 페이지를 동시에
  열어도 DB를 매번 두드리지 않는다. `app.js`에서 전체 no-store 미들웨어보다
  **앞에** 붙여 이 지시가 살아남게 했다.
- 웹사이트 링크는 `http(s)`만 건다. 기업이 적어 준 값이 그대로 들어오므로,
  스킴이 없으면 `https://`를 붙이고 그 밖의 것(`javascript:` 등)은 링크로
  만들지 않는다.
- 로고는 아직 없다. `book_logo`는 "받았다/아니다" 표시일 뿐이고 파일은
  OneDrive에 있어 웹에서 못 읽는다. 이미지 호스팅을 붙이면 그때 넣는다.

## 로컬에서 확인하기

`.claude/launch.json`의 `bloom-crm-backend` 구성으로 백엔드를 띄우고
`http://localhost:8080/d/2026-kic`을 연다. `DATABASE_URL`만 있으면 되고
Firebase 설정은 필요 없다(이 라우트는 인증을 거치지 않는다).
